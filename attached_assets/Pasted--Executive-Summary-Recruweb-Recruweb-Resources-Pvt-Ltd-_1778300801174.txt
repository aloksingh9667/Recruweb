## 2. Structured Extraction of Content  
For each content type, we identify how to locate and parse data from HTML. We expect:  

- **Job Listings**: These likely appear as a listing or search results. We will crawl the Jobs section and follow “next” links for pagination. For each Job detail page, extract fields such as title, job ID, description, location, salary, requirements, posted date, employment type, and company name. E.g. using BeautifulSoup or Scrapy, we might do: 
  ```python
  jobs = soup.select("div.job-listing")
  for job in jobs:
      title = job.select_one("h2.title").get_text()
      location = job.select_one(".location").get_text()
      # ...
  ```
  Extract any links to full job pages for detailed fields like description and skills.  

- **Company Profiles**: If Recruweb lists client or partner companies, scrape the list and detail pages. Fields might include company name, industry, size, location, and a description. For example, we might select `div.company-card` entries.  

- **Candidate Profiles**: Many job sites allow candidates to create profiles. If publicly accessible (no login), extract fields like name, current position, skills, location, and contact info (if any public). *If login is required, note that these profiles are unavailable*.  

- **Contact Info**: The “Contact Us” page often includes address, phone number, email, etc. We would grab the address text and any tel/mailto links. Example:  
  ```python
  address = soup.select_one("section.contact .address").get_text()
  email = soup.select_one("a[href^='mailto']").get("href")
  phone = soup.select_one("a[href^='tel']").get("href")
  ```  

- **FAQs/Help Docs**: The FAQ or Help sections usually list question-answer pairs. We can locate each Q&A pair (e.g. as `div.faq-item`) and extract the question text and the answer text.  

- **Blog Posts**: Scrape the blog listing to get post titles, authors, dates, and URLs. Then visit each post to extract the full content, tags, and comment count if any.  

- **Terms & Privacy**: Static pages under “Terms” or “Privacy” contain legal text. We can treat the entire page as content (possibly split by headings).  

- **API/Integration Docs**: If Recruweb provides an API or integration documentation (common in tech services), crawl those pages to extract endpoint definitions, request/response formats, etc.  

For all pages, we will use an HTML parser (e.g. BeautifulSoup, Scrapy’s selectors) to locate elements by CSS classes or tags. Dynamic content (if any) may require rendering with Selenium or using available JSON endpoints. At each step, we will skip any content behind authentication and respect `robots.txt`.  

## 3. Normalized Data Schemas

  - `company`: string [“Recruweb Resources Pvt. Ltd.”]

  - `employment_type`: string [“Full-time”]

## 4. Chatbot Intents and Entity Mapping  
To build an AI assistant, we map data fields into **intents** and **entities**. For example, users might ask about job availability, company info, or site policies. Key intents include job search, company inquiry, candidate information, contacting support, FAQs, etc. We identify relevant entities (slots) from schema fields, such as `job_title`, `location`, `company_name`, and `faq_question`. Below is a mapping table with sample utterances and responses:

| **Intent**            | **Entities/Fields**          | **Example User Query**                 | **Chatbot Response (using data)**                           |
|-----------------------|------------------------------|----------------------------------------|-------------------------------------------------------------|
| `search_job`          | `job_title`, `location`      | “Show me *Software Engineer* jobs in *Noida*” | “Here are Software Engineer jobs in Noida: Job123 (Full-time at Recruweb), Job456 (Full-time at XYZ Corp).” |
| `get_company_info`    | `company_name`               | “Tell me about *Recruweb Resources*.” | “Recruweb Resources Pvt. Ltd. is an HR service firm based in Noida. […]" |
| `get_candidate_info`  | `candidate_name`             | “Show profile of *Neha Kushwaha*.”    | “Neha Kushwaha is a senior recruiter with 5 years of experience, skilled in HR management.” |
| `contact_support`     | *(none or `contact_type`)*   | “How can I reach support?”             | “You can email us at info@recruweb.com or call +91-120-XXXXXXX.” |
| `faq_query`           | `faq_question`               | “How do I change my password?” (if in FAQ) | “Our Help Center says: *You can change your password by clicking the gear icon…”.” |
| `blog_latest`         | *(none)*                     | “What’s new on your blog?”            | “Recent posts include ‘AI in HR 2026’ and ‘Navigating Remote Hiring’.” |
| `terms_privacy`       | *(none)*                     | “What is your privacy policy?”        | “Our privacy policy states that we collect only business-related data, not personal info【60†L216-L224】.” |
| `api_info`            | *(if API doc exists)*        | “List API endpoints.”                | “Available endpoints: GET /api/jobs (list jobs), POST /api/apply (submit application)…” |

*Table 3: Example intent/entity mappings with sample utterances.*  Entities in *italics* above correspond to schema fields. For instance, the `search_job` intent would use fields like `title` and `location` from job postings. The chatbot should be trained so that queries map to these intents and the bot can fill responses by querying the structured dataset. In Gemini, these fields would be used in the *context* or prompt to produce accurate answers. 

## 5. Sample Gemini API Payloads  
Using Google Gemini’s chat API (which is OpenAI-compatible)【51†L263-L272】, we prepare JSON payloads. For example, to answer a job search query, we can pass system instructions, context, and user message. Sample JSON for Gemini might be:

```json
{
  "model": "gemini-3-flash-preview",
  "reasoning_effort": "low",
  "messages": [
    {"role": "system", "content": "You are a helpful assistant for Recruweb. Use the provided data to answer user questions."},
    {"role": "user", "content": "Find Software Engineer jobs in Noida listed this week."}
  ]
}
```

Here, the assistant would use the scraped job database to list matching jobs. Another example – asking about a company:

```json
{
  "model": "gemini-3-flash-preview",
  "messages": [
    {"role": "system", "content": "You are an expert on Recruweb’s content and policies."},
    {"role": "user", "content": "What industries does Recruweb serve?"}
  ]
}
```

The response can be parsed from `response.choices[0].message`【51†L267-L272】. These examples show “prompt templates” with system instructions and user queries in JSON format, ready to send to Gemini. (In practice, you’d programmatically fill the `"content"` with actual user input and possibly relevant knowledge from the database as additional context.)

## 6. Data Quality and Legal/Robots/Privacy Considerations  
- **Missing/Unavailable Data**: If candidate profiles or certain pages require login, note them as “private”. We will only scrape publicly accessible pages. For example, if `/profile/<id>` redirects to login, we skip it. All scraped data should be valid HTML in the public domain.  
- **Quality Checks**: We’ll validate that required fields exist (e.g. a job listing has title/location). Missing fields will be logged. Duplicates (e.g. same job on two pages) will be deduped by `job_id` or URL. Text fields will be cleaned of HTML tags and whitespace.  
- **Robots.txt**: Before crawling, fetch `https://recruweb.com/robots.txt`. We will parse any `Disallow` and `Crawl-delay` rules【35†L268-L277】【60†L324-L334】. If pages like `/api/` are disallowed, we will not scrape them. Respecting `robots.txt` is crucial; ignoring it risks blocks or legal issues【35†L268-L277】【60†L324-L334】.  
- **Rate Limiting**: To avoid overloading the site or being banned, we set delays. Scrapy recommends a delay of 2+ seconds per request【34†L420-L428】. We will throttle to ~1–2 requests/sec and rotate user agents. If needed, use proxies or delay further. These measures balance speed with politeness【34†L412-L421】.  
- **Legal & Privacy**: We will avoid scraping personal data (PII) beyond public business info. Guidelines stress “Avoid PII… don’t scrape names, emails, phone numbers” of individuals【60†L216-L224】. We will focus on business-related content (job details, company info, FAQ text) and redact any unintended PII (e.g. candidate email on a profile) immediately. Since Recruweb is an Indian company, local laws (e.g. India’s IT Act, draft Data Protection Bill) should be considered, but generally public business info is safe.   
- **Copyright & Terms**: The scraped data will be used internally to build a chatbot. We pull “raw facts” (job facts, FAQs) but will not reuse creative text beyond what the user explicitly requests. We will cite data sources in training if needed. We will not republish blog posts verbatim outside the chatbot without permission.  

In summary, we will follow ethical scraping practices: obey `robots.txt`, use reasonable delays, avoid forbidden pages, and respect privacy by skipping any personal or sensitive information【35†L268-L277】【60†L216-L224】.

## 7. Crawling & Data Pipeline  
We propose a modular pipeline: fetch robots.txt → crawl pages → identify page types → extract fields → clean/normalize → dedupe → store. In each step we use robust tools (Python libraries) and log progress. Below is a **Mermaid** flowchart of the pipeline:

```mermaid
flowchart LR
  A[Fetch robots.txt and sitemap] --> B[Crawl seed URLs with rate-limit];
  B --> C[Parse each page; detect type (job, blog, FAQ, etc.)];
  C --> D[Extract fields into structured records];
  D --> E[Clean text, normalize formats];
  E --> F[Deduplicate and validate records];
  F --> G[Store structured data (JSON/DB)];
  G --> H[Use data to build chatbot knowledge base]
```

**Tools & Code**: We will likely use **Scrapy** for crawling (async, polite, pipeline support) or a combination of `requests` + **BeautifulSoup**. Example using Scrapy (from docs)【32†L94-L102】: 

```python
import scrapy
from scrapy.crawler import CrawlerProcess

class RecruSpider(scrapy.Spider):
    name = "recru"
    start_urls = ["https://recruweb.com/"]
    custom_settings = {"DOWNLOAD_DELAY": 2, "USER_AGENT": "Mozilla/5.0"}

    def parse(self, response):
        # Identify links to follow or data to extract
        for href in response.css("a::attr(href)").getall():
            yield response.follow(href, self.parse_page)
    
    def parse_page(self, response):
        if "jobs" in response.url:
            # extract job data
            title = response.css("h1.job-title::text").get()
            # ... other fields
            yield {"job_id": response.url, "title": title}
        elif "blog" in response.url:
            # extract blog data
            yield {"post_id": response.url, "title": response.css("h1::text").get()}
        # ... handle other types (companies, FAQs, etc.)
```

For simpler pages, **requests + BeautifulSoup** could suffice: 

```python
import requests
from bs4 import BeautifulSoup

res = requests.get("https://recruweb.com/contact", headers=headers)

```

We will integrate **retry logic** (exponential backoff on failures) and log any 4xx/5xx errors. The final data will be saved as JSON or loaded into a database (e.g. MongoDB or SQL) for easy querying by the chatbot.

## 8. Security, PII Handling, Compliance Checklist  
- **Secure Storage**: Store scraped data in a secure database or encrypted files, with access controls. Remove any sensitive information (PII) found by mistake.  
- **PII Minimization**: Exclude personal names/emails (except official company contacts) as per compliance.【60†L216-L224】. Anonymize or hash any user-generated content if present.  
- **Consent/ToS**: We will not scrape after logging in, and abide by site terms. We consider Recruweb’s terms: if “Browsewrap” (footer link) applies, risk is lower【60†L324-L334】.  
- **Robots.txt**: Confirm robots rules; do not scrape disallowed directories. Respect any specified crawl-delay【35†L268-L277】.  
- **Copyright**: Use the data to answer queries internally; do not republish blog or prose. Any excerpt used as chatbot answer is brief (fair use for QA).  
- **Rate Limit**: Set delays (~1–2s) and monitor site response to prevent bans【34†L420-L428】.  
- **Monitoring**: Watch for IP blocks (HTTP 429/403) and adjust rate or proxy usage.  
- **Legal Review**: Confirm with legal (if needed) that collecting public business/job data is permitted under Indian law. Avoid scraping any private user profiles.
